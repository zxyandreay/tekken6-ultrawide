# v1.1.0 automatic aspect detection — syscall ABI investigation

## Device evidence

- v1.1.0-dev1/dev2: automatic aspect build loaded but left 3D stretched.
- v1.1.0-dev3: removed PPSSPP aspect querying and hardcoded the known-good 20:9 projection words. This corrected 3D on-device.
- v1.1.0-dev4: retained the exact dev3 PRX and added camera-only CWCheats. 3D and camera presets both worked.

This isolates the failed path to the PPSSPP emulator API / `sceIoDevctl` call boundary rather than the Tekken projection addresses or memory writes.

## Root cause

PPSSPP registers `sceIoDevctl` with a six-argument HLE wrapper. PPSSPP's `PARAM(n)` macro reads argument `n` from MIPS register `A0 + n`, so the six integer/pointer parameters are consumed from:

1. `$a0`
2. `$a1`
3. `$a2`
4. `$a3`
5. `$t0`
6. `$t1`

The temporary local test toolchain used generic MIPS o32. That ABI passes arguments 1-4 in `$a0-$a3` and arguments 5+ on the caller stack. Disassembly of the failed automatic candidate confirmed the `outdata` and `outlen` arguments were stored at `16($sp)` and `20($sp)` before calling the imported `sceIoDevctl` stub.

Therefore PPSSPP did not see the intended aspect-output pointer and output length in `$t0/$t1`, so `GET_ASPECT_RATIO` could not populate the local float correctly.

This matches the independent MHFU v1.2.3 finding that temporary non-PSPDEV test builds were unreliable for PSP syscalls with more than four arguments.

## dev5 test bridge

The local v1.1.0-dev5 diagnostic build keeps generic-o32 compilation but adds a tiny assembly bridge:

```asm
tekken6Devctl:
    lw      $t0, 16($sp)
    lw      $t1, 20($sp)
    j       sceIoDevctl
    nop
```

The bridge receives the generic-o32 call, transfers stack arguments 5/6 into the PSP syscall registers expected by PPSSPP, and tail-calls the normal imported `sceIoDevctl` stub.

No Tekken projection address or patching behavior is changed from the working dev3/dev4 core.

## Production direction

The repository's production plugin source should remain normal PSPSDK C. A canonical PSPDEV build handles the PSP calling convention and should not require the temporary bridge.

Final v1.1.0 package design remains:

- PRX: automatic 3D aspect correction only.
- `PSP/Cheats/ULUS10466.ini`: camera presets only.
- No manual aspect-ratio CWCheats in the v1.1.0 package.
